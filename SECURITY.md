# Безопасность

## Модель угроз

`llm-gate` хранит:

- **API-ключи** к платным/бесплатным LLM-провайдерам (NVIDIA, Groq, OpenRouter, Together).
- **URL-ы прокси с логином/паролем** (если используете платные).

Утечка этих секретов → злоумышленник может потратить ваши лимиты или (для платных аккаунтов) деньги.

## Что защищено

- **Шифрование на диске.** Все ключи и URL прокси шифруются AES-256-GCM перед записью в SQLite. Мастер-ключ — в `~/.llm-gate/master.key` (на POSIX — с правами `0600`).
- **Не уходит в логи.** Ключи маскируются в API-ответах (`nvap•••••••••3456`), пароли в URL прокси замазываются (`socks5h://user:****@host:port`).
- **Loopback по умолчанию.** Оба порта биндятся на `127.0.0.1` — недоступны из локальной сети без явного решения.
- **Bearer-auth на admin API.** При `LLM_GATE_AUTH_TOKEN` оба порта проверяют `Authorization: Bearer <token>`.
- **Docker под non-root.** Контейнер запускается под отдельным UID.

## Что НЕ защищено

- **Доступ к диску = доступ ко всем ключам.** Мастер-ключ и БД лежат рядом, кто читает файлы — расшифрует. Это сознательный trade-off: безопасные хранилища (Keychain/DPAPI) ломают портативность, Docker и CI-юзкейсы.
- **CSRF на admin API.** Защиты от cross-site запросов нет, но локально это не проблема.
- **Rate limit на admin API.** Нет — bearer-токен считается доверенным.

## Рекомендации

### Не открывайте порты наружу без auth-токена

```bash
# Плохо:
LLM_GATE_HOST=0.0.0.0 npm run dev

# Хорошо:
LLM_GATE_HOST=0.0.0.0 LLM_GATE_AUTH_TOKEN=$(openssl rand -hex 32) npm run dev
```

При старте без токена на не-loopback хосте `llm-gate` выводит warning в баннере.

### Не коммитьте `.llm-gate/` и `.env`

Они уже в `.gitignore`. Перепроверьте, если переносите конфиг между машинами.

### Используйте отдельные ключи для llm-gate

Не используйте production-ключи компании. Создайте отдельный аккаунт у провайдера и сгенерируйте ключ только для locally-hosted gateway.

### Бэкап / перенос

Скопируйте всю папку `~/.llm-gate` (или Docker-volume `llm-gate-data`) на новую машину — БД и мастер-ключ должны быть вместе, иначе расшифровать не получится.

## Сообщить об уязвимости

Если нашли security-баг — **не открывайте публичный issue**. Опишите проблему в private security advisory на GitHub или напишите maintainer'у напрямую.
